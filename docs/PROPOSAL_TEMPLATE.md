# ШАБЛОН предложения для агентов (docs/PROPOSAL_TEMPLATE.md)

Назначение: по этому шаблону агент формулирует **предложение** (например, `UI_DOM_PHASE2.md`). Предложение проходит `/judge`; после вердикта из него делается отдельный исполняемый план `<ИМЯ>_PLAN.md` (этапы, DoD, журнал) — шаблон предложения планом **не становится**.

Правила оформления:
- Копируй разделы 0–11 как есть; ненужный раздел не удаляй, а пиши в нём «не применимо, потому что …».
- Факты — только командами (`git log`, гейты, скрипты), с числами и путями. «На глаз» = отклонение, /judge вернёт.
- Скобочные подсказки `<!-- … -->` из своего экземпляра удали.
- Все пути — актуальные (`docs/<кампания>/…`, `src/ui/…`, `scripts/<категория>/…`); ссылка на карту переезда — `docs/README.md`.

## Самопроверка перед отправкой в /judge

- [ ] Предложение содержит D0 «Финальность»: перечислены ВСЕ подвопросы темы и судьба каждого (закрывается этим планом / объявляется постоянным решением владельца).
- [ ] Все точки участия игрока собраны: этап 0 содержит исчерпывающий список явных ок (замены golden, выборы); иных касаний игрока, кроме финальной приёмки, нет.
- [ ] Предложение сверено с `docs/DECISIONS.md` (решения владельца): противоречий нет, затрагиваемые решения упомянуты в разделе 5 или 11.
- [ ] Каждый факт в разделе 2 подтверждён числом/командой, воспроизводимой сегодня.
- [ ] Раздел 4.x «Что НЕ входит» заполнен (пустой = предложение раздуто).
- [ ] Все D-пункты решаемы без вопросов игроку в ходе исполнения (правила, а не остановки).
- [ ] Критерии R проверяемы командой с кодом выхода; W имеют пороги.
- [ ] Есть метрики «до» и способ снять «после» тем же скриптом.
- [ ] Таймбокс и жёсткий стоп указаны; план объявлен неделимым или явно перечислены точки приёмки.
- [ ] Раздел 11 содержит только настоящие развилки (не те, что решаются правилами).
- [ ] Политика сбоев прописана: красный гейт → revert → аварийный отчёт; ветка не сливается сама.
- [ ] Статус в шапке — «предложение (на согласование)»; файл лежит в `docs/<кампания>/<ИМЯ>.md`.
