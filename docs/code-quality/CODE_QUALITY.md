## 1. Резюме (TL;DR)

- Четыре коротких милестоуна, закрывающие тему «инженерные хвосты» окончательно: JSDoc-проход, баррель `state/index.js`, удаление `scripts/archive/`, включение смысловых ESLint-правил.
- Каждая задача в этой кампании **не имеет следующего «потом»**: JSDoc покрывает весь `src/`, ESLint-правила включаются вместе с исправлением всех своих находок, архив удаляется целиком, баррель переезжает вместе с детекторами (D0).
- Таймбокс: ≤ 3 рабочих дней; жёсткий стоп 4.

## 2. Проблема и факты

- JSDoc: у экспортов `src/` документация в лучшем случае боковыми комментариями; контракт функций неформализован (задача отложена в Приложение E реорганизации и никогда не выполнялась).
- `src/state.js` — баррель на старом месте; перенос был исключён из реорганизации только из-за «зашитых» детекторов URL-подстроки `/src/state.js` в `scripts/gates/ui-check-dom.mjs` и `scripts/gates/ui-review.mjs` и ~23+ импортов.
- `scripts/archive/` — 4 снятых с эксплуатации скрипта с пометками «удалить после <условие>»; условия (квартальная ревизия) отменены `DECISIONS.md` №2.
- ESLint — только стилистические правила (`curly`, padding-line); смысловые (`no-undef`, `no-unused-vars`) выключены — опечатки и мёртвый код не ловятся.

## 5. Технические решения (D-пункты)

- **D0 «Финальность»**: после плана — каждый экспорт целевых каталогов документирован и проверяется гейтом; старого пути `state.js` не существует; `scripts/archive/` пуст и удалён; смысловые ESLint-правила включены с нулём находок. Поводов вернуться к теме нет.
- **D-play**: этап 0 — охват JSDoc и состав правил; финальная приёмка — сводка. Середина — без вопросов; JSDoc-спорные места (что писать) решаются по образцам существующих комментариев, а не опросом.
- **D1** JSDoc — стиль проекта: по-русски, кратко, без воды; инварианты вызывающего обязательны там, где они есть (например, «не пишет в gameState»).
- **D2** Баррель: пути детекторов — единственная «зашитая» правка; всё остальное — механический перенос.
- **D3** ESLint: правила — ошибки (не warnings); подавления `eslint-disable` — запрещены, находка правится.
- Инварианты проекта — по AGENTS.md.

## 9. Риски и меры

| Риск | В/В | Мера |
|---|---|---|
| `no-unused-vars` вскрывает мёртвый код, удалять страшно | Сред/выс | Классификация: неиспользуемое = удалить (это не изменение поведения); сомнительное — в финальный отчёт списком, а не в «потом» |
| JSDoc-проход расползается по времени | Сред/сред | Жёсткий охват этапа 0; JSDoc только на экспортах, не на каждой строке |
| Детекторы URL ловятся не везде (строковые сборки) | Низк/выс | Grep `state\.js` по скриптам/тестам на этапе 0 — полный список до правки |
| `docs:check` даёт ложные срабатывания (реэкспорты) | Сред/низк | Правило: JSDoc у терминального экспорта; реэкспорт-баррель — исключение с комментарием |

## 10. Альтернативы

1. **JSDoc руками без гейта** — дрейф: через месяц половина пропадёт; отклоняется.
2. **Оставить баррель на месте навсегда** — допустимо (чистая косметика), но тогда вопрос закрывается постоянным решением «state.js остаётся» — D0-совместимо; рекомендация — перенести (дешевле один раз).
3. **ESLint только warnings** — не гейт, шум; отклоняется.
