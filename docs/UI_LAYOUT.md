# UI layout check — измеряемая проверка вёрстки

Вёрстка игры — абсолютные координаты в Phaser, поэтому любая правка может сдвинуть
соседей. Чтобы не ловить это глазами, есть автоматическая проверка:
**матрица вьюпортов × состояний → аудит объектов сцены → размеченные скриншоты**.

## Быстрый старт

```
npm run ui:check:quick                 # 3 вьюпорта x 16 состояний (~1 мин)
npm run ui:check                       # полная матрица: 9 вьюпортов x 16 состояний (~5 мин)
npm run ui:check:dom                   # DOM-мастерская: 7 вьюпортов x 26 рядов (гейт)
npm run ui:check -- --viewports p390 --states settings,craft   # точечно
npm run ui:check -- --no-baseline      # показать ВЕСЬ долг, а не только новое
```

Результат — `shots/ui-check/` (папка в .gitignore):
- `<viewport>__<state>.png` — скриншот с рамками нарушений; номер рамки = номер в отчёте
  (красная — ошибка, оранжевая — предупреждение, приглушённая — известный долг);
- `report.md` — сводка и список новых нарушений; `report.json` — всё в машинном виде.

Код выхода `1` — есть **новые** ошибки (сверх baseline), console errors или сбой прогона.
`--strict` — новые предупреждения тоже валят прогон.

## Правила аудита (`src/dev/uiAudit.js`, пороги — `UI_RULES`)

| Правило | Серьёзность | Что ловит |
|---|---|---|
| OVERLAP | error | объекты пересекаются, не будучи вложенными друг в друга |
| OVERFLOW | error | текст/элемент вылезает за свой фон (карточку, кнопку, панель) |
| TEXT-COVERED | error | текст лежит под своим фоном (порядок отрисовки/depth) |
| OFFSCREEN | error | текст/кнопка вне канваса |
| MIN-FONT | error < 8 CSS px, warn < 10 | кегль **на экране** (с учётом FIT-масштаба) слишком мал |
| ROW-NAME | error | имя ряда улучшений шире лимита карточки |
| PADDING | warn | текст ближе 4 px (кнопка) / 6 px (панель) к краю своего фона |
| TOUCH-TARGET | warn | зона нажатия меньше 40 CSS px (мобильный) / 24 px (десктоп) |
| BUTTON-GAP | warn | зазор между кнопками 0…4 px |
| MISALIGNED | warn | одинаковые кнопки в ряду/колонке сдвинуты на 1…4 px |
| EDGE | warn | текст/кнопка ближе 4 px к краю канваса |

Слепые зоны (честно): `Graphics`/частицы не измеряются; бокс текста приближён (минус 3 px);
9-slice-фаска входит в bbox фона; прозрачные поля иконок считаются частью bbox;
анимируемые в момент замера тексты (всплывающие подписи) и объекты GameScene с твином пропускаются.
Аудит не заменяет взгляд на картинку: он ловит измеримое, а «красиво ли» — нет.

## Матрица (`scripts/lib/ui-matrix.mjs`)

Вьюпорты: 1920×1080, 1366×768, 1280×720, 1024×768, 844×390 (телефон-ландшафт), 768×1024,
412×915, 390×844, 360×640. Состояния: fresh, tutorial, daily, mid, mid-scrolled, deep, **stress**
(предельные числа и самые длинные названия), unlock-ready, settings, settings-stress, offline,
map, craft, boss, boss-reward, player-down.

Новый экран/модалку **обязательно** добавьте как состояние в `STATES` (seed + `setup`).
Нет состояния — нет проверки.

## Baseline («известный долг»)

`tests/ui-check/baseline.json` — нарушения, существовавшие на момент внедрения проверки.
Они не валят прогон, но видны в отчёте (приглушённые рамки, колонка «долг»). Валит только **новое**.
Сигнатура нарушения = правило + сцена + подписи объектов (цифры → `#`), без координат.

- `--update-baseline` — заменить baseline текущим состоянием (после осознанного исправления долга
  или принятого изменения; в коммите должно быть видно, что долг **уменьшился**, а не вырос);
- `--merge-baseline` — слить по максимуму (если нарушения «мерцают» между прогонами);
- Не добавляйте в baseline новые нарушения, чтобы «позеленить» прогон — исправьте вёрстку.

## Репорт из игры (для вас)

В dev-сборке (`npm run dev`) на устройстве/в браузере, где видите проблему:
- **F8** — живое наложение нарушений (вкл/выкл);
- **F9** — скачать `ui-report-*.png` (скриншот с рамками) и `ui-report-*.json`
  (вьюпорт, состояние игры, открытые экраны, список нарушений и объектов).

Приложите оба файла к задаче. Агент воспроизводит один в один:

```
npm run ui:check -- --replay path/to/ui-report-*.json
```

Replay открывает те же вьюпорт, сохранение и экраны, делает аудит и размеченный `shots/ui-check/replay.png`.

## Как добавить правило

Правило — блок в `auditItems()` (`src/dev/uiAudit.js`): работает с плоским списком `items`
(экранные bounds, `order` — порядок отрисовки, `layer` — основной слой/скролл-камера).
Добавили правило — добавьте строку в таблицу выше и прогоните `--no-baseline`, чтобы оценить шум.

## Связь с другими проверками

`scripts/ui-review.mjs` + `npm run test:ui` — **golden-регрессия** (фиксирует текущую картинку;
не знает, что «правильно»). `ui:check` — **нормативная** проверка (знает правила). Нужны обе.
Перед сдачей любой UI-правки — ещё и стиль-гейты `npm run format:check` и `npm run lint`
(Prettier/ESLint; см. `AGENTS.md`, раздел «Стиль кода»).
Список дальнейших улучшений — `docs/UI_LAYOUT_TODO.md`.

## DOM-слой (`src/dom/`, пилот мастерской)

Мастерская рисуется обычным DOM (`src/dom/`) поверх канваса и включена по умолчанию
в проде и dev; Phaser-экран удалён после пилота (G3 = go). Для неё действуют свои гейты:

```
npm run ui:check:dom                    # 7 вьюпортов, 26 рядов с прокруткой, 0 ошибок — гейт
npm run ui:tokens:css                   # голых px/rem/em вне tokens.css — нет
npm run test:dom-golden                 # tolerant-diff эталона DOM-панели (порог 0.5% пикселей)
```

**С этого этапа полный прогон UI = `npm run ui:check` + `npm run ui:check:dom`.**
`ui:check:dom` снимает страницу (`page.screenshot`) и проверяет DOM по `getBoundingClientRect`
с порогами `UI_RULES` (`rules.minFontCss`, `rules.minTouchCss`, `rules.minPadding`,
`rules.mobileMaxWidthCss`): пересечения только по видимой части скролла, шапка и крестик
входят в проверку. Размеченные PNG — `shots/ui-check/<viewport>__craft-dom.png`,
JSON-отчёт — `shots/ui-check-dom/report.json`; код выхода ≠ 0 при новых ошибках.

Размеры DOM — только токены: `npm run dom:tokens` генерирует `src/dom/tokens.css` из
`src/ui/theme.js` (+ `DOM_EXTRA` в `scripts/gen-dom-tokens.mjs`), проверка дрейфа —
`npm run dom:tokens -- --check`. Ручные правки `tokens.css` запрещены.

`ui:check` (Phaser) для состояния `craft-dom` делает только скриншот: display-list аудит
не применим (под DOM-панелью затемнённый HUD, его кегли — известный долг Phaser-аудита).
