### 0.5. Политика сбоев (аварийное завершение вместо паузы)

1. **Красный обязательный критерий внутри этапа:** до 2 попыток исправления **в рамках допустимых изменений** (пути, имена, формат, комментарии, конфиги). Не исправлено → `git revert` коммитов этого этапа (история не переписывается), запись в журнал.
2. **После отката — аварийное завершение:** финальный отчёт «план не выполнен»: выполненные этапы, место сбоя, причина, состояние ветки (`chore/repo-reorg` остаётся для разбора, **в `master` не сливается**), бэкап-ветка и бандл. Частичный результат автоматически не принимается; решение о продолжении принимает игрок **после** отчёта (новым запуском).
3. **Превышение бюджета этапа более чем на 50 %** — запись в журнал, работа продолжается; **общий жёсткий стоп — 8 дней**: при достижении — аварийное завершение по п. 2.
4. **Нельзя «лечить проверку»:** не ослаблять `UI_RULES`, пороги гейтов, не расширять `tests/ui-check/baseline.json`, не обновлять golden и не скрывать объекты ради зелёного прогона.

## 8. Правила исполнителя (кратко)

1. Один этап — один набор коммитов, Conventional Commits (`refactor|chore|docs|test|style(repo|ui|game|scripts): …`); «переносы» и «правки путей» — разные коммиты; стиль-коммиты не смешивать с логикой.
2. Только `git mv`; без правок содержимого файла в коммите переноса.
3. Никаких изменений поведения; необходимость такого изменения = сбой этапа (0.5).
4. Не менять `baseline.json`, golden, `UI_RULES`, пороги гейтов.
5. Не переписывать исторические документы (D7).
6. После каждого этапа — полный набор гейтов из DoD; отчёт о путях — grep, а не «на глаз».
7. Не останавливаться и не задавать вопросов после старта; развилки — по 0.4; сбой — по 0.5.
8. Применённые скиллы — в отчёте: `Skills: <файлы>`.
9. Комментарии-обоснования голых чисел не удалять.

## Приложение D. Конфигурация стиля (блок S) — готовые тексты

Версии пакетов фиксируются при установке (`npm i -D --save-exact prettier eslint @stylistic/eslint-plugin`); файлы ниже применяются **как есть** (решение 0.4), корректировки допустимы только при красном гейте в dry-run (запись в журнал).

**`.prettierrc`**
```json
{
    "printWidth": 120,
    "tabWidth": 4,
    "useTabs": false,
    "semi": true,
    "singleQuote": true,
    "trailingComma": "none",
    "arrowParens": "always",
    "bracketSpacing": true,
    "endOfLine": "auto"
}
```
`trailingComma: "none"` — текущий код без висячих запятых; `"es5"` добавил бы запятые во все многострочные объекты и массивы (тысячи правок без пользы). `endOfLine: "auto"` — в репозитории `core.autocrlf=true`: рабочее дерево CRLF, индекс LF; принудительный `lf` перепишет рабочее дерево и сломает `format:check` на Windows.

**`.prettierignore`**


```js
import stylistic from '@stylistic/eslint-plugin';

const rules = {
    curly: ['error', 'all'],

        'error',

    },
    {
```

Заметки для dry-run: (1) `function-call-argument-newline` не включается — переносами аргументов владеет Prettier; (2) при несовместимости версий плагина и ESLint — зафиксировать совместимую пару (запись в журнал); (3) `// prettier-ignore` — по правилу 0.4.

## Приложение E. Заготовка отдельного плана «JSDoc и комментарии» (НЕ входит в этот план)

Бывшее «окно J»: ручной проход ИИ по файлам; по оценке /judge — 40–60 ИИ-сессий при подходе «по 2–3 файла из 118», высокий конфликт-риск. Если понадобится, оформляется **отдельным неделимым планом** (например, `docs/CODE_JSDOC_PLAN.md`) по запросу, после фазы 2. Основные положения:
1. JSDoc — у **экспортируемых** функций, классов и методов-миксинов: назначение одной фразой; `@param`/`@returns` где не очевидно.
2. Боковые `//`-комментарии не удалять: перенос на строку над стейтментом; обоснования голых чисел неприкосновенны.
3. Внутри функций — только короткие комментарии-заголовки шагов; «стены кода» — пустыми строками; деструктуризация параметров > 4 полей — по строке на поле, с группами.
4. Проверка: dist-хэш до = после; `ui:tokens` без изменений; AST-сравнение изменённых файлов (хелпер на `espree`); `format:check`, `lint`.
5. Объём плана ограничить списком папок (без `scripts/`, `tests/`); без остановок — как и все планы (результат всей партии папок или аварийное завершение).
