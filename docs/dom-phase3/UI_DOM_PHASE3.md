## 1. Резюме (TL;DR)

- Переносим на DOM **все оставшиеся формы**: пакет статус-модалок (ежедневная, оффлайн, «вырубило», награда за босса — M2) и список улучшений с вкладками/мультипокупкой (M3).
- После фазы 3 на DOM живут **все** модалки и форм-экраны игры; на Phaser навсегда остаётся только игровой слой: HUD, бой, босс, шахта, обучение (решение №1 `DECISIONS.md`).
- Судьба каждой поверхности зафиксирована в разделе 4.4 — по завершении ни одной «не решённой» формы не остаётся (D0 «Финальность»).
- Таймбокс: ≤ 5 рабочих дней; жёсткий стоп 7.

## 2. Проблема и факты

### 2.1. Что имеем
- Статус-модалки (`src/ui/phaser/statusModals.js`, 379 строк): 4 Phaser-окна с общей логикой очереди в `UIScene` (`tryShowDailyModal`, флаги `_offlineOpen/_dailyOpen/_bossRewardOpen/_playerDownOpen/_pendingDaily`), на DOM — только заготовка реестра (`pending: true`) и сценарии.
- Список улучшений (`src/ui/phaser/upgrades.js` + `gear.js`): ~26 улучшений, 2 вкладки «Оборудование/Усиления», мультипокупка x1/x10/x100/МАКС (`getBulkCost/buyBulk` в `state.js`), прогресс-бары, скролл, секция «Снаряжение» в бою.
- Долг аудита по их состояниям (baseline фазы 2): daily/offline/player-down по 19, boss-reward 31 нарушений MIN-FONT — снимается заново на этапе 0.

### 2.2. Цена
Статус-модалки видит каждый игрок ежедневно; список улучшений — самый частый экран; обе поверхности — главный источник вёрсточных правок (история fix-коммитов: upgrades — самый правимый файл UI после настроек).

### 2.3. Корневая причина
Та же, что в пилоте: ручная раскладка в Phaser; лечится тем же паттерном DOM-формы.

## 4. Объём работ (милестоунами)

### 4.1. Этап 0 — предстартовый (все явные ок игрока — здесь, до работ)
1. **Порядок M2 → M3** — подтверждение (рекомендация: именно так).
2. **Судьба «Снаряжения в бою» (`gear.js`)** — вопрос №2 раздела 11; по ответу фиксируется в объёме M3 или в постоянные Phaser-слои.
3. **Судьба карты** — вопрос №3 раздела 11; по ответу вносится в постоянные решения в финале.
4. Подтверждение целевых вьюпортов: действующая матрица 8 вьюпортов (включая p375).
5. Технический прогон полного набора гейтов — зелёный; замер p95 списка улучшений **на Phaser-пути** (baseline для M3) и переприёмка baseline нарушений по состояниям статуса.

### 4.2. M2 — пакет статус-модалок (1–1.5 дня)
Реализация строго по §6 плана фазы 2 (шаги 3.1–3.10 наследуются по ссылке): `statusMessages.js`, 4 снимка моста, DOM-контроллер `statusModals.js` на `modal.js`, фасад `show*/hide*` с флагами, очередь и D3 (все модалки теперь DOM: z-порядок статус > настройки > мастерская; boss-reward/player-down закрывают мастерскую и карту), кнопки без Esc/фона, реестр + golden 1280×720 и 390×844 на каждый kind, `verify-status-dom.mjs` (SM1–SM9, Q1–Q5), `dom-status-phone.html`.

### 4.3. M3 — список улучшений (2–3 дня)
- DOM-экран `upgrades.js`: вкладки, ряды (имя/уровень/цена-доход/прогресс/кнопка), x1/x10/x100/МАКС, скролл с сохранением позиции; снаряжение — по решению этапа 0.
- Мост: снимок уровней/цен/доступности/дельт; формулы и записи — только `state.js` (`buyBulk`, `canBuy`); **оптимистичное обновление ряда** сразу после клика (до следующего тика снимка) — обязательное требование отклика.
- Производительность: p95 ≤ Phaser-baseline + 2 мс на полном списке; диф по рядам (как в мастерской); виртуализация — только если p95 не влезает.
- Тексты — `upgradesMessages.js`; гейты — реестр (`upgrades-dom`, `upgrades-stress-dom`, сиды mid/stress), golden 1280×720 и 390×844, `verify-upgrades-dom.mjs` (сценарии: покупка x1/пакет/МАКС/отказ, вкладки, скролл-позиция после ресайза, тач/дрожание, паритет текстов, откат флагом).

### 4.4. Финальная классификация (D0 — заполняется без остатков)

| Поверхность | Судьба |
|---|---|
| Мастерская, настройки | DOM — сделано (фазы 1–2) |
| Ежедневная, оффлайн, «вырубилось», награда босса | DOM — этот план (M2) |
| Список улучшений (+вкладки, мультипокупка) | DOM — этот план (M3) |
| Снаряжение в бою | M3 или постоянный Phaser — ответ на этапе 0 |
| Карта | Постоянный Phaser или отдельное будущее предложение — ответ на этапе 0 |
| HUD, бой, босс, шахта, обучение | Постоянный Phaser (DECISIONS №1) — вопрос закрыт навсегда |

По финалу плана в `docs/DECISIONS.md` вносится итоговая строка «классификация слоёв закрыта: …» — тема «что где живёт» не открывается повторно.

### 4.5. Что НЕ входит
HUD/бой/босс/шахта/обучение (DECISIONS №1 — навсегда), экономика/сейвы/баланс, токенизация Phaser-экранов, редизайны, удаление Phaser-путей (отдельная кампания `phaser-cleanup`, идёт после приёмки фазы 3).

## 5. Технические решения (D-пункты)

- **D0 «Финальность»** (шаблон, обязателен): после плана не остаётся открытых вопросов по размещению форм; каждая строка таблицы 4.4 закрыта «перенесено» или «постоянный Phaser».
- **D-play «Точки участия игрока»** (шаблон): этап 0 — список ок из 4.1; финальная приёмка — скриншоты 8 вьюпортов, `dom-status-phone.html`/`dom-upgrades-phone.html`, проверка на телефоне. В середине вопрос игроку невозможен; непредвиденная развилка = аварийный стоп.
- **D1** Паттерн формы — как фаза 2 (vanilla + `renderKeyed`, снимок 150 мс, PUBLISH_MS прежний).
- **D2** Источник правды — только `state.js`/`state/*`; запись `gameState.*` в DOM запрещена (grep-гейт).
- **D3** Слои: после M2 все модалки DOM; z-токены: статус > настройки > мастерская; очередь daily остаётся в `UIScene` (поведенческая логика).
- **D4** Тексты — единые модули сообщений для обоих путей на время переходного окна; после `phaser-cleanup` дублей не остаётся.
- **D5** Флаг отката: `phaserForms=status,upgrades` — каждая форма откатывается независимо; провал любого R формы = автооткат этой формы, остальные продолжаются.
- **D6** Фасад `UIScene` (имена методов/флагов) сохраняется для DevPanel/скриптов/аудита.
- **D7** Закрытие: статус-модалки — только кнопка; список улучшений — паритет с текущим поведением (Esc не закрывает игровой экран).
- Инварианты проекта (токены, алиасы, git mv, Conventional Commits, «не лечить проверку») — по AGENTS.md.

## 6. Критерии успеха

### 6.1. Обязательные (R) — на каждую форму; провал любого R = автооткат формы
R1 паритет поведения (сценарии формы скриптом) · R2 тач: тапы не проваливаются, дрожание ≤10 px, свайп не жмёт · R3 геометрия: `ui:check:dom --form <form>` 8 вьюпортов 0/0, интерактив ≥40 px, горизонтального скролла нет · R4 нет регрессий остального (полный набор гейтов) · R5 слои/очередь (ST9-подобные, Q1–Q5) · R6 тексты/логика без дублей (grep) · R7 DOM-golden стабилен 3 прогона · R8 откат флагом работает.

### 6.2. Желательные (W)
W1 LOC формы ≤ Phaser × 1.3 (тесты не штрафуются) · W2 бандл ≤ +15 КБ gzip на форму · W3 p95 ≤ baseline + 2 мс (для M3 — на полном списке).

## 7. Метрики: до и после
Строки формы (`pilot-loc.mjs --form`), нарушения по состояниям (`ui:check`/baseline, снять на этапе 0), gzip (`metrics:gzip` — метод зафиксирован в baseline фазы 2 §9), p95 (`pilot-frame-p95.mjs --form`; baseline списка снять на этапе 0), fix-счётчики — только справочно (`metrics:fixcount`).

## 9. Риски и меры

| Риск | В/В | Мера |
|---|---|---|
| Очередь модалок: одновременный показ, гонки таймеров 400/900 мс | Сред/выс | Q1–Q5 из фазы 2; тайминги гасятся `waitForFunction`, не снами |
| 26–40 рядов × обновление 150–250 мс | Сред/выс | Диф по рядам; p95-замер обязателен; виртуализация при необходимости |
| Оптимистичный отклик разойдётся с `state.js` | Низк/выс | Ряд перерисовывается из снимка; клик — только вызов state-функции; расхождение ловит verify |
| Мультипокупка/цены в UI | Низк/выс | Только вызовы `getBulkCost/buyBulk` |
| Снаряжение завязано на GameScene | Сред/сред | Решение на этапе 0; при «входит» — связка через фасад, при «нет» — навсегда Phaser |
| Две системы дольше плана | Сред/сред | Флаг только на время кампании; снос — `phaser-cleanup` сразу после приёмки |
| Телефон не проверен вовремя | Сред/низк | Автономные снимки `dom-*-phone.html` в чекпоинте каждого M; финальная приёмка — конец плана |

## 10. Альтернативы

1. **Только M2, список оставить в Phaser навсегда** — снимает меньше половины правок, самый частый экран остаётся источником багов; отклоняется, но judge вправе выбрать (тогда M3 оформляется постоянным решением — D0 соблюдён).
2. **Переносить всё сразу одним махом без приёмки форм** — теряется паритет-контроль; отклоняется.
3. **Карта в объём фазы** — игровая сцена (камера/анимации), выигрыш не доказан; по умолчанию нет (вопрос №3).
