### 0.4. Политика сбоев, аварийные стопы и откат

- Красный обязательный критерий этапа → до 2 попыток исправления в рамках этапа; не исправлено → `git revert` этапа, аварийное завершение с отчётом, ветка не сливается.
- **D-play — аварийный стоп по рендеру:** пробный прогон на `windows-latest` красный из-за **рендера** (шрифты/растеризация GPU-less Chromium), а не из-за тайм-аутов, и не лечится окружением за 2 попытки (кэш, версии, ретрай) → кампания останавливается, владельцу выносится выбор: (а) M1 сейчас, M2 — отдельной кампанией (порт `scripts/lib/dev-server.cjs` на кросс-платформенный + пересъёмка golden с покадровым «ок» владельца); (б) иное решение владельца. **Запрещено:** ослаблять пороги tolerant-diff/pixel-diff и `UI_RULES`, править `baseline.json`, пересоздавать golden в рамках этой кампании. Детали — Приложение C.
- Расхождение «локально зелёное, в CI красное» (пути/CRLF/тайминги) — класс багов CI, правится в этой кампании; если M1 на ubuntu не переносится по путям/CRLF — автоматическое правило: M1 переезжает на `windows-latest` (проще, чем чинить скрипты вне кампании), запись в журнал.
- Превышение бюджета этапа > 50 % — запись в журнал и продолжение; жёсткий стоп 3 дня — аварийное завершение.
- Откат этапа — `git revert` коммитов этапа; пробный workflow удаляется всегда (DoD этапа 0). Слияние ветки — только игроком после финального отчёта.

## 10. Исходы и условия пересмотра (из вердикта)

- **Зелёный финал:** игрок сливает `ci/gates-pipeline` в `master` → на `master` пайплайн зелёный, деплой прошёл после гейтов → TODO закрыт, кампания `ci` закрыта.
- **D-play стоп сработал:** кампания закрывается отчётом; предпочтительный исход — «M1 сейчас, M2 отдельной кампанией» (порт `dev-server.cjs` + пересъёмка golden с «ок» владельца); M2 выпадает без продления таймбокса.
- **Репозиторий станет приватным** → Windows-минуты платные: пересчитать в пользу ubuntu с новым golden-набором и портом `dev-server.cjs` (решение владельца).
- **Golden пересняты на Linux и `dev-server` кросс-платформенный** → M2 переезжает на `ubuntu-latest` (быстрее, дешевле).
- **Появится PR-поток** → ruleset с обязательными проверками — решение владельца, запись в `docs/DECISIONS.md`.
- **Состав гейтов к старту отличается от Приложения A** (очередь кампаний добавила/переименовала гейты) → правка Приложения A по сверке 0.2а, запись в журнале; новый гейт — только через правку workflow (D0).

## 12. Правила исполнителя (кратко)

1. Один этап — один набор коммитов; **Conventional Commits**: `ci(gates): …`, `ci(ui): …`, `ci(deploy): …`, `chore(ci): …`, `docs(ci): …` — тип маленькими, описание с маленькой без точки.
2. CI вызывает **только npm-алиасы**; новых путей к скриптам в workflow нет (`scripts:check` — гард).
3. **Нельзя лечить проверку:** не ослаблять пороги tolerant-diff/pixel-diff и `UI_RULES`, не править `tests/ui-check/baseline.json`, не пересоздавать golden; golden — только по ручной команде владельца.
4. Секретов в CI нет; `pull_request_target` не используется; права джоб — минимальные (`contents: read`; pages/id-token — только выкладка).
5. Селф-хостед не рассматривается; версии Node — одна (`.nvmrc`).
6. Любое отклонение — запись в журнал с причиной; тихих отступлений нет; `question` после старта не используется (единственное исключение — вопрос этапа 0 и D-play стоп).
7. Превышение этапа > 50 % — запись и продолжение; жёсткий стоп 3 дня — аварийное завершение (0.4).
8. Временные вещи (пробный workflow, контрольные красные шаги) удаляются тем же этапом, в котором созданы.
9. Применённые скиллы указывать в отчёте: `Skills: <файлы>` (по INDEX.md прямых совпадений нет).

**Джоба `gates` — `ubuntu-latest` (M1, 10 команд; состав сверяется с `AGENTS.md` на этапе 0 — D7):**

1. `npm run format:check`
2. `npm run lint`

4. `npm run scripts:check`
5. `npm run layers:check`
6. `npm run ui:tokens`
7. `npm run ui:tokens:css`
8. `npm run dom:tokens -- --check`
9. `npm run docs:check`
10. `npm run build`

**Джоба `ui` — `windows-latest` (M2, 4 команды):**

11. `npm run test:ui`
12. `npm run ui:check:quick`
13. `npm run test:dom-golden`
14. `npm run ui:check:dom`

**Ручные опции (`workflow_dispatch`, вход `full_checks`):** `npm run ui:check` (полный) · `npm run metrics:p95`.

**Цепочка деплоя:** `deploy` ← `build` (needs `[gates, ui]`). Итого: **14 автоматических** + 2 ручных.

## Приложение B. Параметры workflow (сводка; значения — по D5/D8/D9)

| Параметр | Значение |
|---|---|
| Файл | `.github/workflows/deploy.yml` (единый: gates + ui + build + deploy) |
| `on.push` | все ветки; `paths-ignore: [docs/**, *.md]`; джобы фильтруются по ref |
| `on.pull_request` | `branches: [master]`; **не** `pull_request_target` |
| `on.workflow_dispatch` | вход `full_checks` (boolean, default false) |
| `concurrency` | group `${{ github.workflow }}-${{ github.ref }}`; `cancel-in-progress` — кроме `master` |
| `permissions` | workflow: `contents: read`; джобы выкладки: `pages: write`, `id-token: write` (как сейчас) |
| Node | `node-version-file: .nvmrc` (= 24) во всех джобах |
| Кэш | npm (`cache: npm`); `ms-playwright`: `%USERPROFILE%\AppData\Local\ms-playwright` (только `ui`) |
| Браузеры | `npx playwright install chromium`, без `--with-deps` |
| Артефакты | `if: failure()` у `ui`: `shots/ui-check/`, diff-PNG golden, лог; `retention-days: 3` |
| Тайм-ауты | `timeout-minutes` = ×3 медианы этапа 0, значения с комментарием |
| Условие `ui` | push `master` / `pull_request` / `workflow_dispatch` |
| Условие `build`+`deploy` | push `master` / `workflow_dispatch`; `build.needs: [gates, ui]` |

## Приложение C. Протокол аварийного стопа D-play

1. **Триггер:** пробный прогон `trial-ui` (windows-latest) красный; причина — **рендер** (drift golden / шрифты / растеризация GPU-less Chromium), не тайм-ауты; 2 попытки лечения окружением (кэш, версии, ожидания готовности) не помогли.
2. **Действия исполнителя:** остановить кампанию; ничего не «чинить» в порогах; удалить/оставить пробный workflow по состоянию ветки (откат `git revert` этапа 0); составить аварийный отчёт владельцу.
3. **Содержание отчёта:** таблица drift по каждому golden (числа из гейтов), логи упавших шагов, замеры времён; два варианта на выбор владельца: (а) **M1 сейчас, M2 отдельной кампанией** — порт `scripts/lib/dev-server.cjs` на кросс-платформенный + пересъёмка golden на linux/другой машине с покадровым «ок» владельца (пороги не ослабляются); (б) иное решение владельца.
4. **Запрещено в любом исходе:** ослабление порогов tolerant-diff/pixel-diff, `UI_RULES`; правки `tests/ui-check/baseline.json`; пересоздание golden в рамках этой кампании; включение селф-хостеда.
5. **Журнал:** запись «D-play стоп, причина, дата, решение владельца» — в раздел 11; в `docs/README.md` статус кампании обновляет игрок/владелец после решения.
