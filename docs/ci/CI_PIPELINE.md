# CI: пайплайн гейтов (предложение)

Статус: **предложение (на согласование; ждёт вердикта /judge)** · Дата: 2026-11-17
Основание: полный набор гейтов существует и стабилен, но запускается только вручную агентом; пункт TODO «ui:check:quick в обязательную приёмку — добавить в CI, когда появится пайплайн» из `docs/UI_LAYOUT_TODO.md` не закрыт, потому что пайплайна нет. Последняя из пяти кампаний: автоматизирует финальный состав гейтов, сложившийся после `code-quality`.
Связанные документы: `docs/UI_LAYOUT.md` (гейты), `AGENTS.md`, `docs/DECISIONS.md`, `scripts/README.md` (алиасы — единственный способ запуска).
Исполнитель: агент (одиночный режим) · Источник запроса: решение владельца 2026-11-17.

> Это **не исполняемый план**. После согласования делается `docs/ci/CI_PIPELINE_PLAN.md`.

## 1. Резюме (TL;DR)

- Поднимаем CI: гейты проекта выполняются автоматически на каждый push/PR и на ручной запуск, отчёт — короткая сводка «что красное».
- Состав CI = **полный обязательный набор** (быстрые гейты на каждый push; браузерные и тяжёлые — отдельной джобой/по расписанию), зафиксированный списком в этом предложении; после этой кампании состав меняется только через правку CI (иначе расползание).
- Таймбокс: ≤ 2 рабочих дней; жёсткий стоп 3.

## 2. Проблема и факты

- Сейчас защита от регрессий — дисциплина агента (AGENTS.md): гейты запускаются, только если агент не забыл; единственный машинный барьер — pre-commit (prettier/eslint на staged-файлах).
- Полный набор тяжёлый: `ui:check`/`ui:check:dom` поднимают dev-сервер + Playwright (десятки прогонов, минуты), `test:ui` — 4 сценария, `build` — сборка. Без CI эти гейты исторически «падали незаметно» (внешний долг реорганизации жил неделями).
- Репозиторий имеет `origin` (GitHub); Playwright-браузеры ставятся командой (факт: `npx playwright --version` — 1.65.0 на машине владельца).

## 3. Что уже есть и переиспользуется

Все гейты запускаются npm-алиасами (гард `scripts:check` гарантирует, что алиас = существующий файл) — CI просто вызывает алиасы. `lib/dev-server.cjs` — управляемый dev-сервер для браузерных гейтов. Полный список команд — в DoD кампаний (D14-набор реорганизации + дополнения фаз).

## 4. Объём работ (милестоунами)

### 4.1. Этап 0 — предстартовый (вопросы игроку — здесь и только здесь)
1. **Раннер**: GitHub Actions на `origin` — доступен? Если репозиторий приватный/нужен селф-хостед — решение здесь (вопрос №1 раздела 11; рекомендация: GitHub Actions).
2. **Триггеры и лимиты**: push в любые ветки — быстрые; PR/ручной запуск — всё; лимит времени джобы (рекомендация: 20 мин).
3. **Секреты**: если деплой/SDK-ключи нужны в CI — какие (для гейтов деплой не требуется; ожидание — секретов нет).
4. Локальный прогон всех джоб-команд — зелёный; замер времени каждой команды (в журнал) для сборки матрицы.

### 4.2. M1 — базовый пайплайн (0.5–0.75 дня)
Джоба `gates` (node 20, `npm ci`, без браузера):
`npm run format:check` · `npm run lint` · `npm test` · `npm run scripts:check` · `npm run layers:check` · `npm run ui:tokens` · `npm run ui:tokens:css` · `npm run dom:tokens -- --check` · `npm run docs:check` (после `code-quality`) · `npm run build`.
Отчёт: одна сводка упавших шагов; кэш npm.

### 4.3. M2 — браузерные гейты (0.75–1 день)
Джоба `ui` (Playwright с кэшем браузеров): `npm run test:ui` · `npm run ui:check:quick` · `npm run test:dom-golden` · `npm run ui:check:dom`.
Правило: `ui:check` (полный, тяжёлый) и p95/приёмки — по ручному запуску (`workflow_dispatch`) и перед релизными слияниями; в CI на push не входит — иначе джоба на 30+ минут.

### 4.4. M3 — правило обязательности (0.25–0.5 дня)
- Красная CI = блокер слияния в `master` (правило в `AGENTS.md` и `docs/UI_LAYOUT.md`).
- Локальный pre-commit остаётся (стиль); CI — целостность.
- Расхождение «локально зелёное, в CI красное» (CRLF/тайминги) — класс багов CI, правится в этой кампании, не переносится.

### 4.5. Что НЕ входит
Деплой/выкладка в прод (владелец публикует вручную — отдельное решение владельца, если понадобится), ночные soak-прогоны,coverage-отчёты, раннеры других платформ.

## 5. Технические решения (D-пункты)

- **D0 «Финальность»**: после плана CI существует, зелёный на `master`, состав гейтов зафиксирован списком в CI-конфиге и в `AGENTS.md`; пункт TODO «добавить в CI» из `UI_LAYOUT_TODO.md` закрыт; тема «автоматизация гейтов» закрыта — новые гейты добавляются правкой конфига CI, а не новыми кампаниями.
- **D-play**: этап 0 — раннер/триггеры/лимиты/секреты; финальная приёмка — зелёный прогон и сводка. В середине вопросов нет; недоступность раннера (нет прав, биллинг) = аварийный стоп этапа 0, работа не начинается.
- **D1** CI вызывает только npm-алиасы (никаких путей к скриптам — гард алиасов остаётся единственным источником).
- **D2** Красная CI = блокер слияния; исключений «потом посмотрим» нет.
- **D3** Тайм-ауты браузерных гейтов — с запасом ×3 от локального замера (антифлейк-порог CI выше локального).
- Инварианты проекта — по AGENTS.md.

## 6. Критерии успеха

### 6.1. Обязательные (R)
R1 пайплайн зелёный на `master` и на тестовой ветке · R2 падающий гейт красит пайплайн и виден в сводке одной строкой · R3 состав джоб = зафиксированный список (M1+M2), упомянут в `AGENTS.md` · R4 время джобы `gates` ≤ 5 мин, `ui` ≤ 15 мин (от замеров этапа 0) · R5 ручной запуск тяжёлых гейтов (`workflow_dispatch`) работает · R6 README/AGENTS содержат бейдж/инструкцию.

### 6.2. Желательные (W)
W1 кэш ускоряет повторные прогоны ≥ 2× · W2 уведомление о красном пайплайне (почта/телеграм — по возможности платформы, без внешних сервисов).

## 7. Метрики: до и после
Время каждой команды локально (этап 0) vs в CI; число гейтов, выполняемых автоматически (до: 0; после: 13+2 ручных); число ручных шагов перед слиянием (до: «помни полный набор»; после: красное/зелёное видно в пайплайне).

## 8. Таймбокс
Этап 0 — 0.25 · M1 — 0.5–0.75 · M2 — 0.75–1 · M3 — 0.25–0.5 · финал — 0.25. Итого ≤ 2 дня, жёсткий стоп 3.

## 9. Риски и меры

| Риск | В/В | Мера |
|---|---|---|
| Браузерные гейты флакуют в CI (тайминги, шрифты) | Сред/выс | D3 (тайм-аут ×3); фиксированные порты; шрифты из репозитория; повтор один раз для network-независимых шагов |
| Джоба `ui` дольше 15 мин | Сред/сред | Матрица только по обязательным состояниям; полный `ui:check` — ручной запуск |
| Нет доступа к Actions (приватный репо/квоты) | Низк/выс | Решается в этапе 0 (вопрос №1); нет раннера — кампания не начинается (D-play) |
| Красная CI игнорируется | Сред/выс | D2 + правило в AGENTS.md; `/review` проверяет статус CI ветки перед вердиктом |

## 10. Альтернативы

1. **Локальный git-hook на полный набор** — тормозит каждый коммит на минуты, не виден команде; отклоняется (pre-commit остаётся только для стиля).
2. **Селф-хостед раннер на машине владельца** — зависит от включённого ПК; отклоняется, если Actions доступен (вопрос №1).
3. **Автоматизировать сразу всё, включая полный `ui:check`** — push-джоба 30+ минут; отклоняется (ручной запуск).
