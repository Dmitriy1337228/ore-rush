## Шаг 3. Вердикт

**Вердикт: принять с правками.**

**Обоснование.** Репозиторий публичный (Actions и Windows-раннеры бесплатны), CI вызывает только npm-алиасы, состав гейтов зрелый — идея и таймбокс обоснованы. Но план исходит из трёх неверных допущений: что есть PR-поток (в истории прямые коммиты в `master`), что деплой ручной (`.github/workflows/deploy.yml` уже публикует каждый push без гейтов) и что гейты переносимы на Linux (`scripts/lib/dev-server.cjs` — `cmd /c npx` и `taskkill`, golden-PNG сняты на Windows). Без правок «красная CI = блокер» остаётся лозунгом, M2 даёт красный CI с первого дня, а `docs:check` (алиаса нет) красит M1.

**Обоснование отклонения.**
- *Всё на `ubuntu-latest` (как в плане по умолчанию)*: требует портирования `dev-server.cjs` и пересъёмки golden с покадровым «ок» владельца (`UI_LAYOUT_TODO.md`) — отдельная кампания, ломает таймбокс; D3 (×3) лечит тайминги, а не растеризацию шрифтов.
- *Селф-хостед раннер*: зависит от включённого ПК (против идеи «гейты не падают незаметно») и в публичном репо исполняет чужой код форк-PR на машине владельца; Windows-раннер GitHub даёт ту же среду бесплатно.
- *Отложить M2 (вариант Pragmatist)*: оставляет вёрстку — главную причину кампании (origin пункта TODO `ui:check:quick` в CI) — ручной; отклонено, т.к. на `windows-latest` портирование не нужно. Отложение остаётся аварийным выходом (см. правку 3).
- *Ruleset с обязательными PR в этой кампании*: требует смены потока работы владельца (решение владельца, не агента); машинный барьер обеспечивается гейтингом деплоя.

**Условия пересмотра.**
- Репозиторий станет приватным → Windows-минуты платные: пересчитать в пользу ubuntu с новым golden-набором и портом `dev-server.cjs`.
- Golden пересняты на Linux и `dev-server` кросс-платформенный → M2 переезжает на ubuntu (быстрее, дешевле).
- Пробный прогон этапа 0 на `windows-latest` показал drift golden/baseline, не лечимый окружением → вариант «M1 сейчас, M2 отдельной кампанией» (Pragmatist) становится предпочтительным.
- Появится PR-поток → включить ruleset с обязательными проверками (добавить в `docs/DECISIONS.md` решением владельца).

## Ответы на раздел 11

1. **Раннер.** GitHub Actions на `origin` — **да, вопрос закрыт фактом**: репозиторий публичный, Actions уже используются (`deploy.yml`). Селф-хостед — **не рассматривается**. ОС: M1 (`gates`) — `ubuntu-latest`; M2 (`ui`) — **`windows-latest`** (среда golden и `dev-server.cjs`). Если пробный прогон M1 на ubuntu краснеет из-за путей/CRLF — M1 переезжает на Windows (проще, чем чинить скрипты вне кампании).
2. **Триггеры.** Согласен с оговорками: полный `ui:check` и p95/приёмки — только `workflow_dispatch`. Остальное **пересобрать под реальный поток**: push в `master` = M1+M2; push в прочие ветки = M1; `pull_request` в `master` = M1+M2 (когда появятся; не `pull_request_target`); `workflow_dispatch` = M1+M2 + опция полного `ui:check`. `paths-ignore` для `docs/**`, `*.md`; `concurrency` с `cancel-in-progress` для всех ref, кроме `master`.
3. **Красная CI — блокер.** Принцип — **да**; механизм — **гейтинг деплоя**: публикация в Pages возможна только после зелёных `gates` и `ui` на том же коммите (единый workflow `needs:` либо `workflow_run` со статусом `success`). Формулировка «исключений нет» заменяется: **единственный выход из красного — фикс или `git revert` красного коммита, приоритетнее новой работы; обхода гейта в деплое нет**. Ruleset/branch protection — вне кампании, включается решением владельца при переходе на PR-поток.

## Обязательные правки для плана (`CI_PIPELINE.md`)

1. **§3/§4.5/§9:** убрать утверждение «деплой владелец делает вручную». Зафиксировать факт: `deploy.yml` существует и публикует каждый push в `master` без гейтов. В объём (§4) добавить правку `deploy.yml`: деплой зависит от зелёных `gates` и `ui`; сама логика выкладки не меняется. В «Что НЕ входит» оставить: новые способы деплоя, секреты.
2. **§4.1 (этап 0) — добавить обязательный пробный прогон:** временный workflow (`workflow_dispatch`) запускает на `windows-latest` `test:ui`, `ui:check:quick`, `test:dom-golden`, `ui:check:dom` против текущих golden/baseline **без их изменения**. Фиксировать: зелёное/красное, drift по каждому golden, время каждой команды, время `npm ci` и установки Chromium. Все замеры R4/D3 берутся отсюда (в CI), а не с машины владельца. Вопросы владельцу в этапе 0 сокращаются до подтверждения «Pages/деплой работает» (раннер — не вопрос).
3. **D-play — аварийный стоп:** если пробный прогон красный из-за рендера (шрифты/GPU-less Chromium), а не из-за тайм-аутов, — **кампания останавливается и выносится владельцу** выбор: (а) M1 сейчас, M2 отдельной кампанией (порт `dev-server.cjs` + пересъёмка golden с «ок» владельца); (б) иное. Не ослаблять пороги tolerant-diff/pixel-diff и `UI_RULES`, не править `baseline.json`, не пересоздавать golden в рамках этой кампании (AGENTS.md: «нельзя лечить проверку»).
4. **§4.2 состав M1:** убрать `docs:check` до появления алиаса; добавить в «Зависимости»: «`docs:check` включается одним коммитом при закрытии `code-quality`». Версия Node — **одна для `gates`, `ui` и `deploy`** (рекомендация: 24 — версия, на которой гейты проверены; README `tests/characterization`), вынести в один источник (`.nvmrc` или переменная workflow); расхождение 20/22/24 из плана устранить. После смены версии в деплое — сравнить `metrics:gzip` бандла до/после.
5. **§4.3/§5 триггеры:** заменить на схему ответа 2 (с `concurrency`, `paths-ignore`, `permissions: contents: read`, безсекретные `pull_request`).
6. **D0 — один источник правды:** список гейтов живёт только в workflow-файле; `AGENTS.md` и `docs/UI_LAYOUT.md` ссылаются на него и не дублируют перечень. Поправить счётчики в §7: сейчас M1 = 9 команд (10 с `docs:check`), M2 = 4, итого 13 (14); «13+2 ручных» привести к факту.
7. **D2:** переписать по ответу 3 (гейтинг деплоя; revert/fix как единственный выход; ruleset — вне кампании).
8. **D3:** тайм-ауты — ×3 от медианы замеров **в CI** (≥5 прогонов), ослабляются только ожидания загрузки/готовности, не пороги сравнения. Ретрай: не более одного, только шаги `ui`, при срабатывании — предупреждение и счётчик «flaky» в сводке (`$GITHUB_STEP_SUMMARY`); список карантина/`knownFlaky` **не вводить** (противоречит AGENTS.md). Если за 10 прогонов этапа 0 ретраи не понадобились — не включать вовсе.
9. **R2/R5 — артефакты:** при падении `ui` загружать `shots/ui-check/`, diff-PNG golden и лог (`actions/upload-artifact`, срок хранения короткий); сводка — одна строка на упавший шаг. Кэш: npm и `ms-playwright` (на Windows — `%USERPROFILE%\AppData\Local\ms-playwright`), без `--with-deps`.
10. **§9 риски — добавить:** «рендер Windows-раннера ≠ рендер машины владельца» (мера — правка 2–3); «дрейф golden при пересъёмке на другой машине» (мера: golden обновляются только по ручной команде владельца и прогону в CI); «CRLF/EOL» — при проявлении лечить `.gitattributes` для `golden/*.out`, а не ослаблением сравнения.
11. **Таймбокс (§8):** ≤ 2 дня сохраняется при условии зелёного пробного прогона этапа 0; при сработавшем D-play стопе M2 выпадает из кампании без продления.
