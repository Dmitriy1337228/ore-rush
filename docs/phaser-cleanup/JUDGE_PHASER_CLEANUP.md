## Шаг 3 — вердикт

**Вердикт: ПРИНЯТЬ С ПРАВКАМИ — как рамку одного неделимого сноса, стартующего ТОЛЬКО после исполнения фазы 3 (G-итог по формам записан). В текущем состоянии репозитория предложение исполнять нельзя.**

**Обоснование.** Концепция верна: двойной стек — налог на каждую задачу (§2 предложения), D0 и решения №2/№3 снимают временные гейты. Но предложение построено на состоянии, которого нет: статус-модалки и список сегодня живут на Phaser, `statusModals.js` — не реликт, а единственная реализация, DOM-эталонов для них нет, `golden/ui` не заменяется `golden/dom`, `gear.js` — постоянный Phaser, а общая раскладка модалок (`applyModalsLayout`) обслуживает карту и обучение. Скрипты-потребители (16) фаза 3 и так мигрирует; одно окно после неё — дешевле двух проходов по тем же файлам и сохраняет порядок кампаний; удаление флага раньше G-итога лишает фазу 3 механизма автоотката (D5).

**Обоснование отклонения.**
- *Сносить сейчас, как есть (исполнение без правок):* удаляет живые daily/offline/boss-reward/player-down модалки и красит `test:ui`; опирается на ложное предусловие.
- *Двухшаговый снос «настройки сейчас» (architect):* закрывает скрытую Phaser-модалку настроек раньше, но правит `ui-review`, `ui-matrix`, `verify-*`, `uiAudit.js` дважды (их затем переписывает фаза 3), требует «хирургии» флага и промежуточного состояния — при ограничении «таймбокс ≤ 2–3 дня» дороже, а выигрыш — только месяцы мёртвых 464 строк, которые не ломают игроку ничего. Остаётся резервом.
- *Soak-окно как отдельный день (critic):* не принимается как обязательный; принимается дешёвая форма — два коммита (миграция потребителей → удаление), без дополнительного дня.
- *Заморозить до неопределённого срока:* нарушает дух №3, но отдельного варианта не требуется — «заморозка» уже следует из правила порядка кампаний.

### Ответы на вопросы раздела 11

**Q1. Предусловие «фаза 3 принята, откатов не было» без ожидания деплоя — ПРИНЯТЬ С ПРАВКОЙ.**
«Без ожидания деплоя/релиза» — **да** (№2, №3). Но формулировка «принята» подменяет «исполнена»: сегодня принят вердикт, а не работы. Предусловие (техническое, проверяемое):
(1) фаза 3 **исполнена**: план `UI_DOM_PHASE3_PLAN.md` закрыт, G-итог по каждой строке таблицы 4.4 записан в журнал и, по плану фазы 3, итоговая строка «классификация слоёв закрыта» внесена в `DECISIONS.md`;
(2) для каждой формы со статусом «go» `DEFAULT_PHASER_FORMS` не содержит её, DOM-эталоны (`golden/dom/<form>/`) и `verify-<form>-dom` существуют и зелёные; форма с «автооткатом/постоянный Phaser» **не сносится** (её Phaser-код — единственный путь, а не легаси);
(3) полный набор гейтов зелёный на старте (`format:check`, `lint`, `npm test`, `test:ui`, `ui:check`, `ui:check:dom`, `ui:tokens`, `dom:tokens --check`, `layers:check`, `scripts:check`, `build`);
(4) «откатов не было» заменить на объективное: флаг рантаймовый (`?phaserForms`/`localStorage`), в git его использование не видно — критерий не проверяем; вместо него — п. 2–3 плюс отсутствие открытых репортов игрока по DOM-формам (F9 `ui-report-*.json`).
Объём сноса — **по фактическому G-итогу**, не «всё».

**Q2. `--legacy`-приёмки удалять целиком — ПРИНЯТЬ С ПРАВКОЙ: да, но пакетом «мигрировать потребителей → удалить `withLegacy`/флаг → удалить ветки».**
Сам `--legacy`-режим `verify-settings-dom` и ST14 («откат флагом») удаляются вместе с флагом. Но `withLegacy` стоит в 16 скриптах и принудительно держит Phaser-настройки; удаление «целиком» без миграции перекрасит гейты. Условие удаления: таблица «сценарий старого пути → где теперь покрыт» (престиж/сброс через настройки в `verify-boss`, закрытие настроек поверх daily, клики `ui.soundBtn`); сценарий без пары не удаляется. Не трогать «legacy»-термины сейвов (`verify-offline`). Состав — только grep-инвентаризацией этапа 0, не Приложением A.

**Q3. Golden форм: удалять Phaser-эталоны без повторного покадрового апрува — ЧАСТИЧНО.**
- **Содержимое форм** (тексты, вёрстка, состояния) повторно покадрово не апрувится: паритет принят приёмкой форм (R1–R8, `golden/dom/<form>/`, 8 вьюпортов `ui:check:dom`). Это принимается — но только для форм, у которых DOM-эталоны действительно существуют (сегодня только настройки).
- **Удаление `golden/ui/*` невозможно**: это один сквозной прогон, `test:ui` падает при изменении набора кадров; кадры форм — композиты «форма + Phaser-слой», которых `golden/dom` не покрывает. Операция — **одна перезапись `golden/ui`** (`06_settings_modal`, `07_offline_*`, `12_portrait_modal`, `12_settings_daily`, `20_boss_reward`, `layout_audit_{modal,offline,portrait_modal}.txt`, `run.stdout.txt`, `SHOT_THRESHOLDS`), т.е. D2 «удаление, не перетирание» заменяется на «явное перетирание».
- **Один сводный апрув остаётся обязательным** (план фазы 2 §5.2: обновлять `golden/ui` «только после апрува игроком»; снять правило может только владелец): не покадровый и не по содержимому форм, а **один контакт-лист** перезаписанных композитов + дифф текстовых артефактов — на проверку композиции (дим, z-порядок, позиция поверх HUD, портрет). Апрув выносится **за таймбокс** как точка участия игрока (D-play): ожидание ответа не входит в «≤ 2–3 дня».
- Потеря покрытия (композитов 6 вьюпортов → 2 вьюпорта `golden/dom`) фиксируется в плане явно: либо принимается, либо на этапе сноса в `golden/dom` добавляются недостающие вьюпорты. Исторические `docs/dom-phase2/baseline/phase2/*` — архивируются/остаются как история, в гейтах не участвуют.
