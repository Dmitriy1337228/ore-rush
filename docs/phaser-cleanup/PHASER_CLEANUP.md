## 1. Резюме (TL;DR)

- Удаляем **все** следы двойной реализации форм: Phaser-код `settingsModal.js`/`statusModals.js` (+`gear.js`, если он остался), флаг-откат `phaserForms`/`LEGACY_FORMS_QUERY`, `--legacy`-приёмки, флаговые ветки фасада.
- Мигрируем последних потребителей Phaser-внутренностей (verify-скрипты, `ui-matrix`, `ui-review`, golden) на фасад и DOM-селекторы.
- **Флаг отката не заменяется ничем**: после этой кампании DOM-путь — единственный; тема «две системы» закрывается окончательно (D0).
- Таймбокс: ≤ 2 рабочих дней; жёсткий стоп 3.

## 2. Проблема и факты

- Двойной стек — это ~430+ строк мёртвого по умолчанию кода (`settingsModal.js` 428 строк строится всегда и скрыта — задокументированное отклонение фазы 2), флаговые ветки в `UIScene`, `--legacy`-режимы в приёмках и скриптах (`scripts/lib/forms-flag.mjs`), два набора golden.
- Каждый новый экран/правка обязана поддерживать оба пути — налог на все будущие задачи (стоимость окна отката посчитана в журнале фазы 2, этап 4).
- Потребители внутренних объектов — закрытый список Приложения A плана фазы 2 (DevPanel, `ui-matrix`, `ui-review`, `verify-boss/daily/map/offline/devpanel/mutations`, `uiAudit.js`, скрипты метрик/стендов); после фазы 3 часть уже снята — точный остаток фиксируется на этапе 0 grep-ом.

## 3. Что уже есть и переиспользуется

- Фасад D6 в `UIScene` (методы/флаги) — остаётся единственной точкой входа; потребители, уже работающие через фасад, не трогаются.
- DOM-эталоны форм: создаются при приёмке фазы 3 (`golden/dom/<form>/…`) — замена Phaser-golden не требует новых приёмок.
- `scripts/README.md` — карта скриптов; `layers:check`, `scripts:check` — гарды целостности.

## 5. Технические решения (D-пункты)

- **D0 «Финальность»** (обязателен): после плана grep `isPhaserForm|phaserForms|LEGACY_FORMS_QUERY` — 0; двойной реализации форм не существует; вопрос «откат на Phaser» закрыт навсегда (откатом будущих дефектов DOM-формы занимаются `git revert`-ом, а не флагом).
- **D-play** (шаблон): этап 0 — подтверждение предусловия и состава удаления; финальная приёмка — сводный отчёт grep/gzip/долг. Середина — без вопросов игроку.
- **D1** Фасад `UIScene` сохраняет публичные имена (DevPanel, скрипты, аудит не меняют контракты).
- **D2** Golden: DOM-эталоны — эталон; замена Phaser-golden форм — удаление, не перетирание; регрессия нетронутых Phaser-экранов — нетронута.
- **D3** Бандл: после сноса ожидается уменьшение gzip; рост против baseline-фазы-3 — разбор по файлам, допуск 0.
- Инварианты проекта — по AGENTS.md.

## 6. Критерии успеха

### 6.1. Обязательные (R)
R1 `grep -r "isPhaserForm|phaserForms|LEGACY_FORMS_QUERY"` — 0 совпадений (код+скрипты+доки) · R2 удалённые файлы не существуют, потребители мигрированы (grep по списку этапа 0 — 0) · R3 полный набор гейтов зелёный без расширения `baseline.json` · R4 все verify-скрипты кампании зелёные на DOM-пути · R5 `ui-matrix`: у форм не осталось дублей состояний · R6 долг baseline уменьшен числом, зафиксированным в коммитах · R7 gzip не вырос против замера этапа 0 (ожидаемо уменьшился).

### 6.2. Желательные (W)

## 9. Риски и меры

| Риск | В/В | Мера |
|---|---|---|
| Снос ломает скрытых потребителей (строковые ссылки, скрипты) | Сред/выс | Инвентаризация этапа 0 + `scripts:check`/`layers:check` + grep-отчёт 0 |
| Golden-замена роняет регрессию | Сред/выс | Удаляются только golden форм; регрессионный golden Phaser-экранов не трогается |
| Удаление флага = потеря «пути отхода» | Низк/выс | Осознанное решение владельца (D0); откат дефектов — `git revert` |
| Долг baseline «уменьшить» превращается в ослабление | Низк/выс | Только пересчёт по переключённым состояниям; `UI_RULES` не трогается |

## 10. Альтернативы

1. **Оставить флаг навсегда** — вечный налог двойной поддержки; отклоняется (DECISIONS №2).
2. **Удалять формы по одной вместе с каждой фазой** — дробит снос, удлиняет окна двойной поддержки; отклоняется: один снос после стабилизации дешевле и проверяемее.
3. **Оставить `--legacy` приёмки** — тестирование мёртвого кода; отклоняется (вопрос №2 этапа 0).
