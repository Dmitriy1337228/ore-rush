## Фаза 3b — разбор рисков, заявленных исполнителем

1. **«UI не пишет state» / `doPrestige`+`resetGame` из `settingsScreen`** — нарушения **нет**: D2 прямо разрешает действия вызовами функций state; прямых записей `gameState.*` в DOM-слое ноль; побочные эффекты (звук, сейв, закрытие, `tierChanged`, надпись «+N ★») вынесены в `scene.afterPrestige/afterReset`, которые зовут **оба** пути (проверено диффом `settingsModal.js`: `tryPrestige` → `doPrestige()+afterPrestige()`). Дублей нет.
2. **Тайминг блокировки (просил оценить хрупкость)** — оценка: **низко-средняя, тестовая, не продуктовая**. Критические переходы ждут через `waitForFunction` (открытие формы, `_pendingDaily`), а не сном. Остаточный риск: фиксированные паузы 150 мс и стартовое ожидание 900 мс против таймера daily на 900 мс — на медленной машине таймер может выстреть после очистки `dailyInfo`/`_pendingDaily` в тесте; гонку гасит гард `tryShowDailyModal` (требует `_pendingDaily`), поэтому это флак-риск приёмки, не игры. Продуктовый тайминг корректен: `updateBlockLock` пересчитывается из `refreshUi` каждый кадр, `setFormOpen` синхронно обновляет флаг и реестр.
   💡 Надёжнее заменить фиксированные сны на `waitForFunction(() => ui._pendingDaily || ui._dailyOpen …)` и убрать зависимость от «повезло с таймером».
3. **Скрытая Phaser-модалка** — см. находку №1 (важнейшее процессное замечание ревью).
4. **Порядок монтирования (craft пересобирает `#ui-root`)** — реальная зависимость, подтверждена кодом: `_domSettingsReady = _domCraftReady.then(…)`. Режим отказа тихий: если чанк/цепочка упали, остаётся только `console.error` на старте, а `openModal` после await делает `this.domSettings?.open()` — no-op, кнопка настроек «мёртвая» без видимой ошибки. См. находку №2.
5. **`formsFlag` в `ui/shared`, а не `ui/dom`** — отклонение **обосновано и корректно**: `ui/phaser/settingsModal.js` импортирует `isPhaserForm`, а правило слоёв запрещает `phaser → dom`; `layers:check` зелёный. Путь в Приложении C плана был ошибочен. Журнал запись содержит. Принять.
6. **375 px + H-SCROLL** — правильная реакция на репорт: не точечный хак, а новое правило аудита + вьюпорт в матрице (теперь 8) + ST1f в приёмке. Это усиление гейта, не «лечение проверки».
7. **W1 (LOC 1.35×)** — по правилам 10.4 W-критерии никогда не откатывают форму; обоснование есть (рост — тесты и общий каркас: 436 без каркаса = 1.19×). **Не блокер.**
8. **Слайдер: сейв на `change` и `pointerup`** — для мыши событие `change` и так стреляет на отпускании, для клавиатуры — только `change`; двойной `saveGame` идемпотентен. 🟢 nit, можно дедуплицировать по «последнее сохранённое значение».

- p95 33.3 → 16.7 мс (−50 %), бандл +4.29 КБ (≤ 15), золотые прогоны стабильны, R1–R8 PASS.

### 🟡 [important]
1. **Phaser-модалка настроек строится всегда и остаётся скрытой — отклонение от шага 2.6 плана («при DOM-пути не строится»), не записанное в журнал.** Плановое правило «тихие отступления запрещены» нарушено; в финальном сообщении отклонение раскрыто, но журналом не стало. Функционально безвредно (скрытый контейнер не интерактивен), но: (а) ломает учёт W1/LOC и стоимости окна отката; (б) маскирует будущие правки Phaser-пути. **Требуется до/сразу после слияния:** док-коммит с записью отклонения в журнал (этап 2), либо — в последующей задаче (раздел 8) — ленивая сборка `buildModal` по `isPhaserForm('settings')`.
2. **Тихий режим отказа монтирования настроек.** Цепочка `craft → settings` — необходима сегодня, но отказ цепочки оставляет мёртвую кнопку: `openModal()` после `await` делает `?.open()` без diagnostics. Минимальное лечение: в `openModal` после await, если `!this.domSettings` — явный `console.error`/повторная попытка; системное лечение (последующая задача): убрать перестройку `#ui-root` в `craft.js` (монтировать в выделенный хост), тогда порядок загрузки перестанет иметь значение. Инвариантный тест «настройки открываются после холодного старта» уже есть в ST1 — держать его в обязательных.

5. Двойной сейв слайдера — см. выше, безвреден.
6. Соответствие «ST ↔ L-проверки» для `--legacy` (7 проверок против 28) нигде не сведено в таблицу — интерпретация «эквивалента» разумна, но таблица маппинга в baseline-доке закрыла бы вопрос навсегда.
