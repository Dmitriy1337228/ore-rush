# Долг вёрстки и усиление аудита (предложение)

Статус: **предложение (на согласование; ждёт вердикта /judge)** · Дата: 2026-11-17
Основание: `docs/UI_LAYOUT_TODO.md` — живой документ с недожжённым долгом (MIN-FONT ~470, TOUCH-хвост ~173, OVERLAP 8 золотозависимых, слепая зона скролл-аудита) и незакрытыми улучшениями аудита; категория MIN-FONT — единственный оставшийся крупный блок.
Связанные документы: `docs/UI_LAYOUT_TODO.md` (первоисточник, по завершении — закрывается), `docs/UI_LAYOUT.md`, `docs/DECISIONS.md` (№2 — временные гейты отменены), `docs/dom-phase3/UI_DOM_PHASE3.md` и `docs/phaser-cleanup/PHASER_CLEANUP.md` (меняют состав экранов — долги считаются по актуальному состоянию на этапе 0).
Исполнитель: агент (одиночный режим) · Источник запроса: решение владельца 2026-11-17.

> Это **не исполняемый план**. После согласования делается `docs/ui-debt/UI_DEBT_PLAN.md`.

## 1. Резюме (TL;DR)

- Сжигаем **весь** оставшийся долг `ui:check` и закрываем тему вёрсточного долга окончательно: категория MIN-FONT (портретная сетка + раскладка низких ландшафтов), TOUCH-хвост, OVERLAP-остаток (2 места — на апрувах этапа 0), слепая зона аудита скролл-списков, хвостики миграции компонентов.
- После кампании правило меняется навсегда: **любое новое нарушение аудита = блокер слияния** (долг 0, нечего копить), а апрувы скриншотов идут по постоянному протоколу из `UI_LAYOUT.md`.
- Таймбокс: ≤ 4 рабочих дней; жёсткий стоп 6.

## 2. Проблема и факты

- Долг baseline (последняя фиксация, UI_LAYOUT_TODO §4): 470 = MIN-FONT 470, OVERLAP 8 (золотозависимые), TOUCH-хвост ~173 (числа сняты до фаз 3/сноса — на этапе 0 пересчитываются по актуальному `report.json`).
- MIN-FONT: портрет и 844×390 — кегли 9–14 px при FIT-масштабе 0.5–0.6 дают < 8 CSS px; точечные фиксы не работают, нужна сетка.
- Слепая зона: аудит проверяет только видимые ряды; два инцидента 2026-11-16 (наезд «Крафт 30 мин», NaN-карточки) поймали только F9-репорты игрока.
- Хвостики миграции (осознанные остатки из TODO §2): чипы «Оборудование/Усиления» + `x1`, кнопка спуска `unlockBtn`, HUD-кнопка «Настройки».

## 3. Что уже есть и переиспользуется

Токен-каркас (`theme.js`: FONT_SIZE/SPACE/MIN, пороги `UI_RULES`), гейты (`ui:check`, `ui:tokens` с WATCHED-списком, `ui:check:dom`), протокол покадрового апрува golden («старый/новый кадр», применён на «Снаряжение в бою» −25), пачечная механика сгорания долга с числом в коммите.

## 4. Объём работ (милестоунами)

### 4.1. Этап 0 — предстартовый (ВСЕ явные ок игрока — здесь)
1. **Пересчёт долга** по актуальному состоянию (после фаз 3/сноса): таблица «категория × вьюпорт × состояние» из `report.json`.
2. **Покадровый апрув OVERLAP-остатка (до 8 шт.)**: крестик карты (golden 17_map_open) и «Для rebirth…» (12_portrait_modal) — протокол «старый/новый кадр», как для снаряжения. Игрок даёт ок на каждую замену золот или говорит «оставить как есть».
3. **Правило «оставить как есть»**: если игрок отклоняет замену — нарушение помечается в baseline как **принятый долг** (см. 4.6) и тема OVERLAP закрывается без повторных вопросов.
4. Подтверждение целевых порогов аудита расширения (контраст: WCAG AA 4.5:1 для основного текста; базовая линия подписей; wordWrap) — вопрос №2 раздела 11.
5. Полный набор гейтов зелёный; `metrics:gzip` — замер «до».

### 4.2. M1 — MIN-FONT: сетка, а не заплатки (1.5–2 дня)
- Портретная сетка с крупными кеглями (коэффициенты ориентации в `src/layout.js`/`L.*` — единственный источник чисел) и отдельная ветка раскладки для высоты < 480 px.
- Затрагивает оставшиеся Phaser-экраны (map, tutorial, GameScene-оверлеи) и DOM-токены при необходимости — через `theme.js`/`DOM_EXTRA`, без дублей.
- Долг MIN-FONT → 0 (кроме принятого, если появится по п.3 этапа 0).

### 4.3. M2 — TOUCH-хвост (0.5–1 день)
Пачками по `report.json`: расширение кастомных hit-зон до ≥ 40 CSS px (механика `applyHitArea` уже есть); правило вложенности зон (кнопка в большой зоне не флагается) сохраняется. Долг → 0.

### 4.4. M3 — слепая зона аудита скролл-списков (0.75–1 день)
- `uiAudit.js`/`ui-check`: аудит получает **все построенные ряды** скролл-списков (мастерская, список улучшений), а не только видимые; проверка включает ряды за пределами вьюпорта.
- После включения — добавляются состояния прокрутки в матрицу (`craft-scroll`, `upgrades-scroll`; рост baseline для НИХ запрещён — долг уже 0), golden снимаются.
- Правило TODO «не добавлять состояния до сжигания долга» с этого момента всегда выполнено (долг 0).

### 4.5. M4 — расширение аудита и регламент апрувов (0.75–1 день)
- Новые правила `UI_RULES` (не ослабление — усиление): контраст текст/фон (WCAG AA для основного текста), выравнивание подписей по базовой линии в колонках, wordWrap с 3+ строками.
- В `UI_LAYOUT.md` — постоянный протокол апрува скриншотов: «старый/новый кадр», папка/нейминг, кто даёт ок (владелец), когда обновляется golden.
- Хвостики миграции компонентов (чипы, `unlockBtn`, HUD-кнопка настроек) — закрываются здесь же, отдельной пачкой (последний пункт TODO §2).

### 4.6. Принятый долг — легальный исход (D0)
Категория считается закрытой, если: нарушений 0 **или** оставшиеся помечены в `tests/ui-check/baseline.json` комментарием-маркером «ACCEPTED-BY-OWNER <дата> <причина>» (механика: отдельный JSON-ключ, не расширение списка нарушений) и внесены в `DECISIONS.md`. Молчаливых «висящих» нарушений после плана не остаётся.

### 4.7. Что НЕ входит
Новые экраны/достижения/магазин (для них — правило «новый экран = новое состояние матрицы» уже в AGENTS.md), редизайны, CI (кампания `ci`).

## 5. Технические решения (D-пункты)

- **D0 «Финальность»**: после плана `ui:check` долг = 0 или весь остаток — «принятый» с маркером; тема долга закрыта, новые нарушения — блокер слияния (правило вносится в AGENTS.md/UI_LAYOUT.md финальным коммитом).
- **D-play**: этап 0 — все покадровые ок (список 4.1); финальная приёмка — сводный до/после по категориям + размеченные PNG. В середине вопрос игроку невозможен; «игрок не заметил вопрос» исключается остановкой в этапе 0.
- **D1** Числа раскладок — только в `src/layout.js`/`L.*`/токенах; комментарии-обоснования обязательны (`ui:tokens`).
- **D2** Golden: замены — только по покадровому протоколу этапа 0/финала; «лечить проверку» (расширять baseline, прятать объекты, ослаблять UI_RULES) — запрещено.
- **D3** Расширение аудита — только усиление; существующие пороги не меняются.
- Инварианты проекта — по AGENTS.md.

## 6. Критерии успеха

### 6.1. Обязательные (R)
R1 долг категорий MIN-FONT/TOUCH/OVERLAP = 0 или весь остаток маркерован «ACCEPTED-BY-OWNER» · R2 слепая зона: аудит обнаруживает нарушение в невидимом ряду (инъекционный тест) · R3 состояния прокрутки в матрице с golden и 0 нарушений · R4 новые правила аудита включены и дают 0 на текущем UI · R5 полный набор гейтов зелёный; dist/golden нетронутых экранов не изменены · R6 `UI_LAYOUT.md`/`AGENTS.md` — правило «новое нарушение = блокер слияния» · R7 `UI_LAYOUT_TODO.md` закрыт (все пункты [x] или перенесены в принятый долг).

### 6.2. Желательные (W)
W1 gzip не вырос > +0.5 КБ · W2 время `ui:check:quick` не выросло > +20 % · W3 охват WATCHED `ui:tokens` = все Phaser-файлы.

## 7. Метрики: до и после
Долг по категориям/вьюпортам (этап 0 → финал, таблица в журнал), число маркеров «ACCEPTED», p95 кадра (не должен вырасти от сетки), время гейтов.

## 8. Таймбокс
Этап 0 — 0.25–0.5 · M1 — 1.5–2 · M2 — 0.5–1 · M3 — 0.75–1 · M4 — 0.75–1 · финал — 0.25. Итого ≤ 4 дня, жёсткий стоп 6.

## 9. Риски и меры

| Риск | В/В | Мера |
|---|---|---|
| Сетка MIN-FONT меняет вид экранов → массовая замена golden | Выс/выс | Замены — только на этапе 0/финале по покадровому протоколу; всё, что не апрувнуто, — «принятый долг», не тихая замена |
| Расширение аудита даёт гору новых нарушений | Сред/выс | Включение правил — после сжигания; новые нарушения правятся в том же плане (M4), не переносятся |
| Игрок не даёт ок в этапе 0 | Сред/выс | Этап 0 — обязательная точка остановки; нет ок → нет старта (политика D-play), а не «поехали без ответа» |
| Слепая зона тормозит аудит | Сред/сред | Замер времени гейта; кэш построенных рядов в `ui-check` |
| Пачки hit-зон меняют поведение ввода | Низк/выс | Тесты test:ui + verify-скрипты (тап/свайп) после каждой пачки |

## 10. Альтернативы

1. **Принять весь долг как есть** (маркер на всё) — закрывает тему за один день, но оставляет портрет нечитаемым и слепую зону; отклоняется, judge вправе выбрать для отдельных категорий (тогда D0 соблюдается маркерами).
2. **Точечные фиксы без сетки** — не устраняет причину, долг вернётся; отклоняется (корневая причина §2).
3. **Сначала CI, потом сжигание** — CI фиксирует текущий долг как норму; отклоняется: сжигать надо до автоматизации порогов (порядок кампаний).
