# Контекст проекта: Minecraft Clicker

## Текущий статус
- Этап: разработка игры (адаптив v3: правки по фидбеку 375px — ждёт приёмки; реворк улучшений v4: 26 улучшений, 2 вкладки, мультипокупка v2 принята; цена спуска v4.2: снапшот от якоря; Этап 3 GDD v2: мутации блока — 4 типа, ждёт приёмки; фоны локаций v4 приняты, включая переделанный алмазный)
- Последнее обновление: 2026-11-13

## Стек
- Phaser 4.2.1, JavaScript (ESM), Vite 8
- Шрифты: Monocraft (assets/fonts/Monocraft.ttf, векторный клон шрифта Minecraft UI, OFL-1.1, полная кириллица) — основной; Inter.woff2 — фолбэк. @font-face + preload в index.html, document.fonts.load до старта
- Ассеты: SpriteCook (пиксель-арт, 9-slice метаданные в spritecook-assets.json)
- Платформа: Яндекс Игры (SDK — этап 2, стоят заглушки: sdk-stub.js + sdk/yandex.js)

- src/scenes/UIScene.js — HUD, прокручиваемый список 12 улучшений, кнопка «Спуститься глубже», модалки (настройки/престиж/офлайн), applyLayout (все элементы переставляются по ориентации), драг списка для тача

- src/dev/DevPanel.js — панель разработчика (только dev-сборка, см. Принятые решения)

## Архитектура сцен
- GameScene: фон, блок, частицы, всплывающие цифры, пассивный тик, оффлайн-логика. Запускает UIScene
- UIScene: весь UI. В update() дифф-опрос состояния state.js + события game.events ('ui-refresh', 'tier-changed', 'offline-applied')
- Взаимодействие сцен: registry (blockLocked, offlineInfo) + game.events
- Список улучшений: контейнер listContent, рендерится через отдельную камеру listCam (viewport 320x460) — клиппинг нативный; скролл колесом и драгом меняет listCam.scrollY

## Модель экономики (v4)
- 12 тиров руды: Уголь -> Медь -> Железо -> Серебро -> Золото -> Аметист -> Изумруд -> Рубин -> Сапфир -> Платина -> Уранит -> Алмаз. Спуск обнуляет баланс руды; уровни улучшений сохраняются
- **Цена спуска v4.2: снапшот от якоря + ограниченный каталог**: `price = max(2500 * prestigeMult, 180 * 2.95^tier * anchor)`, anchor = ставка дохода при входе в тир (`gameState.tierAnchorRate`; сбрасывается в unlockTier/forceNextTier/doPrestige, лениво фиксируется при первом обращении — новая игра/старый сейв). Цена НЕ меняется от прокачки внутри тира: покупка никогда не «отбрасывает» накопления, ETA монотонно падает до нуля — пола нет, «накупил всё доступное — переход неизбежен и близок». Блиц гасится СТРУКТУРНО, а не формулой: (а) гейты `tier` в UPGRADES — глубокие машины/множители открываются уровнем шахты (каждый спуск открывает ступень машинной лестницы), (б) капы кликовой цепочки (кирка 30, кувалда 10, гидропресс 8, плазма 6, расщепитель 5) против ко-петли «кирка(+1 flat) ↔ множители» (без капов окупаемость бесконечно-мала на любом тире), (в) кирка/шахтёр growth 2.0 — первый уровень окупается за ~1-2с, каскад самозатухает, (г) цены x3.0/тир = доходу x3/тир — окупаемость инвариантна тиру (при x2.5 относительно дешевеющая прокачка взрывала разгон на глубине). Ставка дохода включает MANUAL_CPS_ASSUME=3 x getExpectedClickGain. В UI: у гейт-запертых рядов «нужно: шахта N» (нумерация с единицы: N = tier + 1, как в ярлыке «уровень шахты: N — Руда»)
- При переходе на тир: цены улучшений x3 (TIER_COST_MULT), доход x3 (TIER_INCOME_MULT) — окупаемость улучшений инвариантна тиру
- Цены: ceil(baseCost * growth^level * 3^tier); формулы дохода — `* 3^tier`
- Блок и частицы меняются на текстуры тира; клик добывает только руду текущего тира; в UI валюта в родительном падеже (TIERS[].gen: «2500 уранита»)
- 26 улучшений в двух вкладках (state.js UPGRADES, поле tab: 'equipment' | 'enhance'). Оборудование (даёт + к клику или пассиву): кирка ∞, кувалда ∞ x1.5, гидропресс ∞ x1.6 (кувалда 5), плазменный резак ∞ x1.7, расщепитель ∞ x1.8, шахтёр ∞ +1/с, робо-рука ∞ 0.5 автоклика/с, бур ∞ +10/с (шахтёр 5), экскаватор ∞ +100/с, фабрика ∞ +1000/с, карьер ∞ +10K/с, мега-фабрика ∞ +100K/с, орбитальная станция ∞ +1M/с, квантовая лаборатория ∞ +10M/с, червоточина ∞ +100M/с, гравитационный резак ∞ +1B/с, сфера Дайсона ∞ +10B/с, техника ∞ x1.25, ИИ-ядро ∞ x1.3 (техника 5). Усиления (всё остальное): динамит 23 ур., золотая жила 25 ур., синергия 25 ур., фокус-линза 10 ур. (сила крита +0.5, динамит 15), рудный магнит 5 ур. (жила +1 к множителю, жила 15), фонарь 10 ур., склад 3 ур.
- **Панель улучшений: 2 вкладки** (Оборудование | Усиления) + кнопка-цикл мультипокупки x1/x10/x100/МАКС. x1/x10/x100 — СТРОГИЕ пакеты: покупается ровно запрошенное количество уровней (ужимается только лимитом уровней улучшения), иначе отказ целиком — кнопка серая, цена показывает стоимость полного пакета («491K» / «... x3» у лимита). МАКС — покупает максимум уровней, на которые хватает руды («508K x8»). **Видимость**: доступны + купленные + первое недоступное в цепочке («анонс» с «нужно: …»), цепочки линейны по requires; buildsRow строит все 26 рядов в контейнерах, refreshUi пересчитывает видимость/позиции каждый кадр
- Престиж: 1T (1e12) алмазов за забег -> звёзды = floor(sqrt(добыто/1e12)), каждая +10% ко всему доходу (постоянно); DIAMOND_INDEX вычисляется по ключу 'diamond'
- Офлайн: ставка 20% + 8%/фонарь (макс 100%), лимит 4ч -> 8ч -> 12ч -> 24ч (склад), меньше 5 минут — окно не показывается
- Офлайн-время: при visibilitychange hidden / beforeunload — saveLastExit() через YandexSDKStub.player.setStats({lastExit}) + localStorage minecraft-clicker-lastExit; расчёт при загрузке и при возврате во вкладку
- Сохранение: localStorage minecraft-clicker-save, версия 4; миграция v1->v4, v2->v4 (тиры 5->12: индекс переводится по ключу руды, tierEarned переносится) и v3->v4 (якорь tierAnchorRate фиксируется лениво). Автосейв 5с, при покупке, при уходе
- Симуляция баланса: node scripts/balance-sim.mjs [cps] [maxHours] — два режима: lazy (без покупок, не доходит до алмазов и за 400ч — дегенерат, не игрок) и greedy (окупаемость быстрее времени до спуска, ~3.7ч = середина целевого коридора 3-5ч); verify: node scripts/verify-economy.mjs (52 чека)

## Принятые решения
- **UI-правило (обязательно): у всего адекватные отступы.** Текст и кнопки никогда не ставятся в притык к краям/фаскам элементов: минимум 10-12px от фасок панелей и карточек, 6-8px внутри кнопок. Перед вёрсткой прикидывать ширину текста под Monocraft (моноширинный и широкий: ~0.6-0.75em на символ) и оставлять запас. Проверять: имя/описание/цена не пересекают зону кнопки, уровень не упирается в край, иконки валют не касаются краёв карточки.
- **Автопроверка вёрстки (обязательно после каждой правки UI):** `node scripts/ui-review.mjs` при поднятом dev-сервере — скриншоты 10 сценариев + layout-аудит через `window.__GAME` (src/main.js отдаёт game): обход объектов сцен, world bounds, поиск пересечений текст/кнопка (перевод рядов в экранные координаты камеры списка, фильтр скрытых контейнеров, глифы текста = бокс минус 3px) и вылезаний содержимого рядов за карточку. 0 нарушений = OK; отчёты в shots_*/layout_audit*.txt. **Не захламлять:** каталог вывода задаётся через `OUT_DIR` (по умолчанию `shots`); после успешной верификации удалять устаревшие папки скриншотов — в проекте остаётся только последняя (актуальный базлайн: shots_v38).
- **Хиты для image с setDisplaySize:** интерактивная зона задаётся в координатах КАДРА текстуры (origin 0.5 не смещает локальное пространство — displayOrigin компенсируется), а не отображаемого размера.
- **Иконки в слотах:** контент текстур смещён/разного разрешения (кирки ~176px, новые иконки 64px) — центрирование и нормировка по alpha-bbox контента (UIScene.iconMetrics/placeIcon, кэш), не по канвасу.
- Вся экономика в state.js (чистые функции, без Phaser) — покрывается node-тестом
- Числа: свой форматтер fmt() до Dc (1e33), дальше e-notation
- 9-slice отступы масштабируются под фактический размер элемента (nsBorders по манифесту)
- Подписи кнопок рендерит движок (Monocraft — пиксельный клон шрифта Minecraft UI; без синтетического bold, фолбэк Inter/monospace) — текстуры кнопок пустые
- SDK: игровой код зовёт только YandexSDKStub (по ТЗ этапа 2 меняется содержимое файла без переписывания логики)
- **Псевдо-обучение (только первый запуск):** UIScene.buildTutorial — затемнение + золотая рамка-подсветка (пульс) + стрелка + подпись над блоком/вкладками. Шаги: 0) клик по кубику (3 клика — шагы 1/2 также наступают по таймеру 6с, если игрок ждёт), 1) вкладка «Оборудование», 2) вкладка «Усиления», 3) финал «Приятной игры!» + кнопка «Играть» (finishTutorial). Флаг gameState.tutorialDone: false в новом сейве, старые сейвы получают true (обучение не показывается), saveGame сериализует автоматически. resetGame() возвращает false — «Полный сброс» в DevPanel показывает обучение заново. Учебные объекты исключены из listCam (cameraFilter).
- **Dev Panel:** src/dev/DevPanel.js подключается динамически в main.js только при import.meta.env.DEV (в production ветка мертва, чанк панели исключён — проверено сканом dist). Активация: клавиша ~ (Backquote) или Shift+D, либо клик по скрытой зоне 20x20 в углу экрана. Функции: +1K/+1M/+1B руды, сброс ресурсов, «Макс всё» (капы на максимум, бесконечные -> 50), принудительный следующий тир, «Полный сброс» (resetGame + очистка lastExit/mockStats + скрытие модалок + tier-changed — игра как при первом запуске), симуляция офлайна 1ч/4ч (тот же код, что и реальный возврат), JSON состояния. HTML-панель поверх канваса (левый нижний угол, полупрозрачная), не в стиле игры.
- **Офлайн-модалка по событию:** UIScene слушает game.events 'offline-applied' — реальный возврат во вкладку и симуляция из DevPanel открывают одно и то же окно (раньше при возврате во вкладку показывалась только всплывашка без модалки)
