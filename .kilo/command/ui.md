# РЕЖИМ ДИЗАЙН-РЕВЬЮ UI/UX — задача: $ARGUMENTS

Ты — основной агент этого режима (текущая модель z-ai/glm-5.3-flash). Режим запускается ТОЛЬКО по явной команде `/ui` и никак не встраивается в основной пайплайн `/team`: общие доски, уставы team-* и их правила здесь не действуют, работа идёт по алгоритму ниже.

## Модель субагента team-ui

Модель берётся из фронтматтера устава (`.kilo/agent/team-ui.md`, сейчас Claude Sonnet 5.5) — в вызовах task `model` и `provider` НЕ указывать, чтобы не перекрывать устав.

## Алгоритм работы (максимум 3 цикла)

1. **Скриншоты.** Определи по $ARGUMENTS, какие экраны/сцены снять. Запусти существующий раннер: `node scripts/ui-review.mjs` (dev-сервер поднимается сам, скриншоты и аудит вёрстки пишутся в `shots/`, порт 5174; переменная `OUT_DIR` задаёт выходную папку). Для точечных сценариев — сними целевые экраны через Playwright с `scripts/lib/dev-server.cjs` во временную папку `.kilo/tmp-ui/` (в git не добавлять).
2. **Ревью.** Вызови субагент `team-ui` через task (модель — из устава): передай пути к скриншотам, цель пользователя, пути к файлам UI-компонентов (чтобы критик видел и картинку, и текущие отступы/стили).
3. **Правки.** Если вердикт `FIX`: внеси правки в вёрстку/стили/UI-код строго по замечаниям, с учётом правил проекта (без лишних комментариев, не ломая логику `src/state.js`).
4. **Контроль.** Повтори снятие скриншотов и вызов `team-ui` для подтверждения исправлений. Всего не более 3 циклов (правка + переснятие + ревью); повторяющиеся [MAJOR] после 3 циклов — эскалация игроку с фото и причиной.
5. **Финал.** Удали временные скриншоты (`.kilo/tmp-ui/`, если не должен попадать в git), проверь `0 console errors` в консоли браузера, выдай краткий отчёт: что найдено на скриншотах, что изменено, финальный вердикт последнего прогона team-ui.
