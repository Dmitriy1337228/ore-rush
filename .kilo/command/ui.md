# РЕЖИМ ДИЗАЙН-РЕВЬЮ UI/UX — задача: $ARGUMENTS

Ты — основной агент этого режима (текущая модель z-ai/glm-5.3-flash). Режим запускается ТОЛЬКО по явной команде `/ui` и никак не встраивается в основной пайплайн `/team`: общие доски, уставы team-* и их правила здесь не действуют, работа идёт по алгоритму ниже.

## Разделение ролей

- **Измеримое** (наложения, вылезание за фон, кегль на экране, отступы, зоны нажатия, зазоры, выравнивание, порядок отрисовки) проверяет аудит `npm run ui:check` (`docs/UI_LAYOUT.md`, скилл `.kilo/skills/ui-layout-check/SKILL.md`). Его вердикт не обсуждается: нарушение либо исправлено, либо его нет.
- **Неизмеримое** (визуальная иерархия, читаемость и «считывается ли главное за 2 секунды», перегруженность, группировка, понятность иконок и подписей, композиция) оценивает субагент `team-ui` по размеченным PNG.

## Модель субагента team-ui

Модель берётся из фронтматтера устава (`.kilo/agent/team-ui.md`, сейчас Claude Sonnet 5.5) — в вызовах task `model` и `provider` НЕ указывать, чтобы не перекрывать устав.

## Алгоритм работы (максимум 3 цикла)

1. **Измерения и скриншоты.** Определи по $ARGUMENTS экраны и вьюпорты, найди соответствующие состояния в `scripts/lib/ui-matrix.mjs` (нет состояния — добавь, это правило проекта) и запусти:
   `npm run ui:check -- --viewports d1280,t768,p390 --states <состояния>`
   (для боя, модалок и мастерской добавь `p360,l844`). Если игрок прислал `ui-report-*.json` (F9 в dev-сборке) — сначала воспроизведи: `npm run ui:check -- --replay <файл>`. Dev-сервер поднимается сам; результат — размеченные PNG и `report.md` в `shots/ui-check/` (рамка с номером = строка отчёта: красная — ошибка, оранжевая — предупреждение, приглушённая — известный долг). Зафиксируй число новых нарушений ДО правок. Если до правок уже есть новые нарушения — сообщи игроку, не чини молча.
2. **Ревью.** Вызови субагент `team-ui` через task (модель — из устава). Передай: пути к размеченным PNG и к `shots/ui-check/report.md`, цель пользователя, пути к файлам UI-компонентов (`src/scenes/ui/*`, `src/scenes/game/*`, `src/ui/*`). `team-ui` сам вправе запускать `npm run ui:check*` и отвечает за оценку иерархии и читаемости; измеримые нарушения он берёт из отчёта.
3. **Правки.** Если вердикт `FIX` или в отчёте есть новые нарушения: внеси правки в вёрстку/стили/UI-код строго по замечаниям, не ломая логику `src/state.js`. Числа раскладки — константами/токенами (`src/ui/theme.js`, `src/ui/listGeometry.js`, `src/scenes/game/*Layout.js`), не «голыми».
4. **Контроль.** Повтори `npm run ui:check` для тех же вьюпортов и состояний и вызови `team-ui` для подтверждения. Критерии выхода: **0 новых ошибок и предупреждений** в затронутых экранах, вердикт `OK`. Перед финалом обязательно прогони `npm run test:ui` (golden) и `npm test`. Не более 3 циклов (правка + ui:check + ревью); повторяющиеся [MAJOR] или нарушения после 3 циклов — эскалация игроку с размеченными PNG и причиной.
5. **Финал.** Проверь `0 console errors` (их показывает `ui:check`), выдай краткий отчёт: что найдено (по правилам аудита и по замечаниям team-ui), что изменено, сколько нарушений было/стало, финальный вердикт последнего прогона team-ui. Если исправлялся долг из baseline — `npm run ui:check -- --update-baseline` и указать, на сколько он уменьшился. Golden-скриншоты (`tests/characterization/golden`) обновляются только по явному «ок» игрока на конкретную картинку.

## Запреты

- Нельзя «лечить проверку»: не добавлять новые нарушения в `tests/ui-check/baseline.json`, не ослаблять пороги `UI_RULES` в `src/dev/uiAudit.js`, не скрывать и не удалять объекты ради зелёного прогона.
- Не коммитить `shots/` и временные файлы; не вливать ветку в master без указания игрока.
