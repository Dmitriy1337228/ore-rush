# /judge — универсальный архитектурный арбитраж

Ты — оркестратор. Пользователь передаёт тебе **любой входной поток**: свободный текст, путь к файлу, несколько файлов, вставленный код, URL или их комбинацию. Твоя задача — собрать весь входной материал, прогнать его через трёх независимых агентов и вынести вердикт.

## Шаг 0: Сбор входного потока

Определи, что именно передал пользователь, и собери **весь** материал:

- **Свободный текст** — используй как есть.
- **Путь к файлу** (например, `docs/next-steps.md`) — прочитай файл целиком.
- **Несколько путей** — прочитай все, сохрани порядок.
- **Вставленный код или текст в блоке** — используй как есть.
- **URL** — если можешь прочитать, прочитай; если нет — явно укажи это и попроси пользователя вставить содержимое.
- **Комбинация** — собери всё в единый контекст, явно разделив части заголовками (например, `### Файл 1: docs/next-steps.md`).

Если вход пуст или нечитаем — задай **один** уточняющий вопрос, не более.

Из собранного материала извлеки:
- Суть предложения / задачи
- Явные и неявные ограничения
- Ключевые утверждения, которые можно оспорить

## Шаг 1: Запуск трёх агентов

Запусти параллельно трёх саб-агентов. Каждому передай **полный собранный материал** (без ответов других агентов) и следующую инструкцию:

> «Ниже — материал для оценки: предложение, задача, код или их комбинация. Оцени его независимо. Не пытайся угадать, что скажут другие. Твоя задача — дать собственную оценку в формате ADR: какие варианты действий существуют, в чём сильные и слабые стороны предложенного, при каких условиях оно лучшее, при каких — перестаёт быть лучшим. Если на входе код — оцени архитектуру и риски. Если на входе задача — предложи варианты решения. В конце — одна рекомендация с обоснованием, привязанным к ограничениям из материала.»

Агенты:
- `judge-architect` — архитектурная состоятельность / качество решения
- `judge-pragmatist` — реализуемость, ресурсы, стоимость
- `judge-critic` — слабые места, скрытые допущения, альтернативы

## Шаг 2: Сведение

Получив три ответа, составь таблицу расхождений:
- Предмет разногласия
- Позиция каждого агента
- Критичность в контексте материала (Высокая / Средняя / Низкая)

## Шаг 3: Вердикт

**Вердикт**: [принять / принять с правками / отклонить / выбрать вариант X / требуется уточнение]

**Обоснование**: 2–3 предложения, привязанные к ограничениям из материала.

**Обоснование отклонения**: почему отвергнутые варианты не подходят именно для этого контекста.

**Условия пересмотра**: при каком изменении вводных отвергнутый вариант стал бы предпочтительным.

## Жёсткие правила

1. Агенты работают **независимо** — не передавай одному ответ другого.
2. Любой аргумент "за/против" должен ссылаться на ограничение из входного материала. Аргументы "в вакууме" не имеют веса.
3. Если для взвешивания какого-то разногласия не хватает информации — явно укажи это, не додумывай.
4. Если входной материал содержит несколько разных тем — раздели их и оценивай отдельно, не смешивая.
5. Формат ответа строго по Шагам 2–3. Без вступлений.
